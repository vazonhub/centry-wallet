# Contributing to Centry

Centry is a personal, offline-first iOS finance tracker. Bug reports, feature
ideas and pull requests are welcome. The authoritative spec lives in the
project vault — [`CLAUDE.md`](CLAUDE.md) and [`docs/`](docs/). Read it before
opening a substantial PR.

## Getting started

Prerequisites: Node.js 22+, npm, a Mac with Xcode (iOS only).

```bash
git clone git@github.com:vazonhub/centry-wallet.git
cd centry-wallet
npm install            # also installs git hooks (husky)
cp .env.example .env   # optional — not needed for a local Build 0

npm run ios            # build & run on the iOS simulator / device
```

> **Expo Go does not work** — the app uses a native tab bar
> (`expo-router/unstable-native-tabs`), which requires a dev client.
> `npm run ios` builds one for you. The telltale failure inside Expo Go is
> `<RNCTabView> Unimplemented component`.

## Checks

CI runs these on every PR — run them locally before pushing:

```bash
npm run format:check   # prettier
npm run lint           # eslint (0 warnings allowed)
npm run typecheck      # tsc --noEmit
npm test               # jest (unit tests)
```

The pre-commit hook (husky + lint-staged) runs prettier and `eslint --fix`
on staged files automatically.

### Tests

Unit tests cover the core logic — above all the **money module** in
`src/utils` (integer minor units, currency conversion, rounding, day
boundaries) — and run on [jest-expo]. Tests live in
`src/**/__tests__/*.test.ts` next to the code they exercise. Money arithmetic
must stay green (see [docs/DATA_MODEL.md](docs/DATA_MODEL.md#тесты-денежной-арифметики)).

```bash
npm test               # run once
npm run test:watch     # watch mode
npm run test:coverage  # with a coverage report
```

[jest-expo]: https://docs.expo.dev/develop/unit-testing/

## Branches and pull requests

- **`develop`** is the default branch and where all development happens.
  Branch off it (`feature/*`, `fix/*`) and open your PR back into `develop`.
- `testing` and `master` are release-cycle branches — PRs into them are made
  by the maintainer only (see [`RELEASE.md`](RELEASE.md)).
- A PR must pass all CI checks. Use the PR template; describe **what** and
  **why**, attach screenshots for UI changes.

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):
`feat: …`, `fix: …`, `chore: …`, `refactor: …`, `docs: …`. Scopes welcome:
`feat(input): …`, `fix(widget): …`.

## Architecture — MVC+

The layering is strict; don't cross it without discussing first. Full detail
in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) and [`CLAUDE.md`](CLAUDE.md).

- `src/db/*` — SQLite, the single source of truth. **SQL lives only here.**
- `src/stores/*` — Zustand stores (in-memory state + settings mirror).
- `src/controllers/*` — orchestration: db/services → stores. The only place
  the view layer meets the data layer.
- `src/views/*` — screens: call controllers, read stores via selectors.
- `src/components/*` — reusable UI without business logic.
- `app/*` — Expo Router 6; every route file is a thin re-export of `@views/*`.

Hard rules (see the full list in `CLAUDE.md`):

- No SQL from view components — go through controllers → `src/db`.
- Money is always integer minor units; format only via `@utils/money`.
- No network requests carrying personal or financial data.
- Never edit `ios/` by hand — it is generated by `expo prebuild`; native
  config belongs in `app.json` and the config plugins under `plugins/`.
- Soft delete only (`deleted_at`), never `DELETE FROM`.

## Code style

- TypeScript strict + `noUncheckedIndexedAccess` — check `arr[i]` for `undefined`.
- Imports: external libraries first, then `@`-aliases, then relative; use
  `import type` for type-only imports.
- Functional components without `React.FC`; props as a separate `interface Props`.
- Themed styles via the `makeStyles(Palette)` factory; colors/radii/spacing
  only from `@theme`.
- Comments in English. UI strings and vault docs in Russian.
