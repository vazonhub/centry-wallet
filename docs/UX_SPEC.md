# Centry — UX и экраны

Продуктовые принципы — в [PROJECT_BRIEF](PROJECT_BRIEF.md). Здесь — конкретные экраны, ядро ввода, онбординг, стартовые данные, пустые состояния.

## Навигация

Таббар:

```
[ Главная ]  [ История ]  ( + )  [ Настройки ]
```

- Кнопка **«+»** живёт в таббаре, а не на главной — ввод доступен с любого экрана в один тап.
- Таббар **плавающий и скруглённый** (отступ 14 от краёв, радиус 26) — дефолт iOS 26.
- **Ввод и просмотр записи открываются шитами** поверх текущей вкладки (`@gorhom/bottom-sheet`), не отдельными экранами.

Технически — Expo Router с нативным таб-баром (паттерн Bsuir: `expo-router/unstable-native-tabs`, требует dev client, не Expo Go). Файлы в `app/**` — тонкие ре-экспорты из `@views/*`.

## Ядро ввода (порядок реализации: интент → экран → виджеты → Siri → пуш)

Всё, что позволяет записать трату, растёт из **одного** `AddTransactionIntent(amount, currency?, account?, category?, note?)`:

1. **Экран ввода** в приложении (шит).
2. **Виджет S** — «можно сегодня», тап открывает ввод.
3. **Виджет M** — «можно сегодня» + потрачено сегодня + три последние записи.
4. **Siri / Shortcuts** — «Добавь трату 12 рублей еда».
5. **Вечернее напоминание** — локальный пуш в 22:00 → экран «что сегодня потратил», ввод пачкой.
6. **(v1.1)** Share Sheet для скриншота банковского пуша — тот же интент на выходе.

## Шит ввода (главный экран продукта — правило 4: ≤4 сек, ≤3 тапа)

- Клавиатура поднята сразу, курсор в сумме. **Ноль тапов до первой цифры.**
- Сверху **чип счёта** — по умолчанию последний использованный. Смена счёта меняет валюту ввода.
- Переключатель типа: **расход / доход / перевод**.
- Категории — один ряд иконок, выбор в один тап, **категория необязательна** (пустая = «без категории»).
- Дата = сегодня, скрыта под «…».
- После сохранения — возврат на предыдущий экран; **ввод нескольких трат подряд без выхода**.

### Перевод (тип «перевод», B12)

Перевод между двумя счетами. Если валюты разные:

- показываем **исходную сумму + валюту** (со счёта-источника), **курс перевода**, **итог** (на счёт-получатель);
- курс подставляется автоматически (из кэша Fawaz), но **исходную сумму, курс и итог можно править вручную** — они связаны и пересчитывают друг друга (правишь курс → пересчитывается итог; правишь итог → пересчитывается курс);
- пользователь волен задать любой итог (хоть 1 USD → 100 000 000 BYN) — приложение не навязывает «правильный» курс, только помогает;
- комиссий нет;
- в БД перевод — **две связанные транзакции** (`transfer_pair_id`), каждая со своим `rate_to_base_e6` на момент записи.

## Главная

Отвечает ровно на один вопрос — **сколько можно потратить сегодня**. Сверху вниз:

1. **Большая цифра:** сумма всех балансов в базовой валюте ÷ дни до зарплаты. Цифра **чернильного** цвета (`--ink`), не зелёная (зелёная читалась бы как «заработано»). Оттенок меняется по порогам использования дневного лимита (**B9**):
   - **зелёный** — потрачено 0–80% дневного лимита;
   - **жёлтый (`--warn`)** — 80–99%;
   - **красный (`--neg`)** — ≥100% (лимит на сегодня исчерпан/превышен).
2. **Плашка carry-over** рядом с цифрой (**B10**) — накопленный за период профицит/дефицит:
   - недотратил в прошедшие дни → сегодня можно больше → **зелёная** плашка `+N BYN`;
   - перетратил → суммарный перебор → **красная** плашка `−N BYN`.
   - Пример: вчерашний лимит 100, потратил 80 → сегодня доступно на 20 больше (плашка `+20`). Потратил 120 → плашка `−20`.
   - Цвет строго по правилу 6 (зелёный=профицит, красный=перебор). Точную формулу расчёта финализируем на этапе 3 (главный экран) — см. [DATA_MODEL](DATA_MODEL.md#carry-over-накопленный-профицитдефицит-b10).
3. **Чипсы счетов** горизонтальным скроллом, баланс в родной валюте счёта, плюс чип «+» для создания счёта.
4. **«Потрачено сегодня».**
5. **Лента последних записей**, сгруппированная по дням, с итогом дня справа.

Единственная настройка, нужная для главной цифры, — **день зарплаты**. Спрашивается **не при старте, а при первом тапе по цифре** (правило 3). Меняется потом в настройках (**B15** — п.10 owner-чеклиста).

## История

- Переключение месяцев стрелками, заголовок «Август 2026».
- Итоги месяца тремя карточками: **пришло / ушло / разница**. Разница красится по знаку.
- **Живой поиск** по заметке, без кнопки.
- Фильтры чипсами: Все · Расходы · Доходы · по каждому счёту.
- **«На что ушло»** — топ-5 категорий горизонтальными полосами. **Это единственная аналитика в приложении:** пирогов и графиков по дням нет (D3, D19).
- Список по дням с итогом каждого дня.
- Тап по записи → **шит деталей:** заметка, категория, счёт, дата, **курс на момент записи**, сумма в базовой валюте. Кнопки **«Править»** и **«Удалить»** (D20).

Список истории — `@shopify/flash-list` (паттерн Bsuir: плоский поток строк с `getItemType`), скролл на 500 записях не должен проседать (приёмка).

## Настройки

Шесть групп. **Ни один из этих экранов не показывается при первом запуске.**

| Группа       | Содержимое                                                              |
| ------------ | ----------------------------------------------------------------------- |
| Счета        | список с балансами, «Добавить счёт»                                     |
| Деньги       | базовая валюта, день зарплаты, курс USD→BYN, категории                  |
| Ввод         | виджет, Siri и быстрые команды, вечернее напоминание, время напоминания |
| Вид          | тема (системная/светлая/тёмная), язык, прятать суммы при сворачивании   |
| Данные       | экспорт в CSV, синхронизация (помечена «v1.1»), удалить все данные      |
| О приложении | оценить, написать разработчику, «данные не покидают телефон»            |

> Экспорт CSV — кнопка есть, реализация v1.0. Синхронизация — v1.1. Редактор категорий — v1.0 (но `is_system` уже в схеме).

## Онбординг — опциональная пропускаемая init-визитка (B11)

Ключевой инвариант сохраняется: **ноль обязательных настроечных экранов**. Приложением можно пользоваться сразу — дефолты создаются автоматически при первом запуске:

- счёт **«Основной»** в автоопределённой базовой валюте (`is_default = 1`; для автора — BYN);
- **восемь** системных категорий расходов;
- **три** системные категории доходов;
- базовая валюта — по региону/локали (**B8**).

Поверх этого на первом запуске показывается **init-визитка** (уточнение владельца, B11): предлагает опционально задать свои счета и источники дохода/расхода. Требования:

- **кнопка «Пропустить» всегда видна** и ведёт прямо в рабочее приложение с дефолтами;
- ничего из визитки не является обязательным — это ускоритель, а не барьер;
- «мгновенный старт» и правило «ввод ≤4 сек» не должны страдать: пропустивший визитку пользователь сразу попадает на рабочий главный экран.

Счета также рождаются **по ходу**: когда пользователь впервые вводит сумму в **другой валюте**, приложение предлагает создать соответствующий счёт **одним тапом** (D7).

Нужны для:
