# Centry — дизайн-система

Визуальный язык: **Liquid Glass на светлой матовой плоскости + моноширинные табличные числа**. Мягкие полупрозрачные блоки со световой кромкой, но жёсткая типографическая дисциплина в данных. **Тёмная тема — отдельный проход, не инверсия.**

Токены живут в `src/theme/` и реэкспортируются из `@theme` (паттерн Bsuir: `colors.ts`, `spacing.ts`, `radius.ts`, `typography.ts` + barrel `index.ts`). Стили — через фабрику `makeStyles(Palette)`, мемоизированную по палитре (см. [ARCHITECTURE §Идиомы](ARCHITECTURE.md#идиомы-перенесённые-из-bsuir-time)).

## Семантика цвета (правило 6 — незыблемо)

**Цвет означает ровно одно.**

- **Зелёный (`--pos`)** — приход денег.
- **Красный (`--neg`)** — удаление или перерасход.
- **`--warn`** — предупреждающий порог для главной цифры.
- Больше цвет ничего не кодирует. Категории имеют собственные иконки/акценты, но семантика приход/расход — только зелёный/красный.

Главная цифра «можно сегодня» — **чернильного цвета (`--ink`), не зелёная** (зелёная читалась бы как «заработано»), и меняет оттенок только по порогам использования дневного лимита (**B9**): **0–80% → зелёный**, **80–99% → `--warn`**, **≥100% → `--neg`**. Плашка carry-over (**B10**): профицит → `--pos` (`+N`), дефицит → `--neg` (`−N`) — строго по правилу 6.

### Что меняется между темами и почему

- **Заливка стекла:** на светлом белый 55 %, на тёмном белый 7.5 %. Стекло должно **осветлять** фон, а не накладывать белое.
- **Световая кромка** остаётся сверху, но падает с `.9` до `.16`.
- **Зелёный** поднимается с `#0f7a4f` до `#4ade80` — тёмный зелёный на тёмном даёт контраст ниже 3:1.
- **Кнопка ввода меняет полярность:** главное действие всегда максимально контрастно к фону (`--btn-bg`/`--btn-ink` инвертируются).
- **Цветные пятна фона** становятся глубокими и тусклыми. Без них стеклу нечего преломлять.

## Типографика

| Роль           | Правило                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------- |
| Текст          | системный (SF Pro Text)                                                                         |
| **Числа**      | `ui-monospace` / SF Mono / Menlo — **ВСЕГДА**, `font-variant-numeric: tabular-nums` (правило 7) |
| Герой          | 44px / 600 / tracking −.05em, моноширинный                                                      |
| Микрозаголовки | 8.5–9px / 750 / uppercase / tracking .12–.20em                                                  |
| Строка списка  | 13px / 560; подпись 8.5px / 650 uppercase                                                       |

В RN: числа рендерятся компонентом с `fontVariant: ['tabular-nums']` и моноширинным семейством. Заводится общий `<Money>` / `<Num>` компонент, чтобы правило 7 не нарушалось руками (деньги форматирует только `@utils/money`, см. [DATA_MODEL](DATA_MODEL.md#денежный-модуль-ts-граница-вычислений)).

## Форма

- **Радиусы:** герой 24 · карточки 16–18 · строки списка 16 · иконки 11 · таббар 26 · шиты 30.
- **Кнопка ввода:** 46×46, радиус 16.
- **Таббар:** плавающий, отступ 14 от краёв экрана.

Токены радиусов — в `src/theme/radius.ts` (`sm/md/lg/xl/pill` + семантические). Отступы — `src/theme/spacing.ts` (`screenPadding`, `cardGap`, и т.п. + `TAB_BAR_HEIGHT`).

## Производительность блюра (правило 9 — незыблемо)

`backdrop-filter` дорогой. Блюр применяется **только** к: **герою, чипсам счетов, таббару, шитам**. Строки списков — полупрозрачная заливка **без блюра**. **Не больше пяти заблюренных вью на экран.**

### Реализация в RN

- Нужен нативный блюр: `expo-blur` (или системный материал iOS 26 через SwiftUI-обёртку — предпочтительно, тогда стекло обновляется вместе с ОС).
- Блюр применяется точечно, счётчик заблюренных вью на экран держим ≤5 (правило проверяется на ревью каждого экрана).
- **В WidgetKit блюр недоступен** — там плоская полупрозрачная заливка.
- Правило блюра **одинаково в обеих темах** (D28).

## Реализация тем (паттерн Bsuir)

- `resolvedScheme: 'light' | 'dark'` живёт **в сторе настроек** (не `useColorScheme()`), считается из `theme: 'system' | 'light' | 'dark'` и держится в лок-степе с нативным `Appearance.setColorScheme` — JS-палитра и нативный `UIUserInterfaceStyle` переключаются атомарно, без мигания.
- Хук `usePalette()` выбирает палитру по resolved-схеме; каждый `useMemo(() => makeStyles(Palette), [Palette])` пересобирается при смене темы.
- `onRehydrateStorage` пере-синкает нативную тему на старте.
